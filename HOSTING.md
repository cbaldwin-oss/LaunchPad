# Hosting the CxAlloy Dashboard (static site + auth proxy)

The dashboard is a fully static bundle — `index.html` + `data/*.json`. Anything that
serves static files behind your auth proxy can host it. Because it uses `fetch()` for
the JSON, it must be served over **http(s)**, not opened as a `file://` path.

## Security rules (do not break)
- The CxAlloy HMAC **secret must never reach the browser.** It lives only in GitHub
  Actions secrets. The browser only ever loads pre-built JSON (or, later, calls a
  server endpoint that signs requests for it).
- Keep the repo that holds the data **private**, behind your auth proxy.

---

## Recommended layout: one private repo, served behind your proxy

Put the pipeline and the dashboard in the same private repo (the one already behind
your auth proxy), so one Action refreshes the data and the host redeploys it:

```
<your-app-repo>/
├─ .github/workflows/refresh-dashboard.yml   # hourly refresh (provided)
├─ sync_logic.py  export_json.py  config.py  utils/   # the pipeline
└─ html-dashboard/            # <-- your static host serves this folder
   ├─ index.html
   └─ data/                   # regenerated by the Action
      ├─ projects.json
      └─ project_50506.json
```

### Steps
1. **Copy the pipeline files** into your app repo: `sync_logic.py`, `export_json.py`,
   `config.py`, and the `utils/` folder. Copy the `html-dashboard/` folder in too.
2. **Add the workflow** at `.github/workflows/refresh-dashboard.yml` (already written —
   it writes JSON to `html-dashboard/data`; change `DASHBOARD_OUT_DIR` if your served
   path differs).
3. **Add repo secrets** (Settings → Secrets and variables → Actions → New secret):
   - `CXALLOY_IDENTIFIER` — from your local `.streamlit/secrets.toml` `[cxalloy] identifier`
   - `CXALLOY_SECRET` — from `[cxalloy] secret`
   *(Copy these yourself; never commit the secrets file.)*
4. **Point your static host** at the `html-dashboard/` folder (GitHub Pages `/docs` or a
   folder root, Cloudflare Pages build output dir, S3 prefix, etc.), and make sure your
   auth proxy covers that path.
5. **Run it once** manually: Actions tab → "Refresh dashboard data" → *Run workflow*.
   Confirm `html-dashboard/data/*.json` updates and the page renders.

### Embedding into an existing page
- **Simplest:** link to `…/html-dashboard/index.html`.
- **Inline:** drop it into an existing page with an iframe:
  ```html
  <iframe src="/html-dashboard/index.html"
          style="width:100%;height:100vh;border:0"></iframe>
  ```
  The page is already responsive, so it fills whatever container it's in.

---

## Alternative: keep two repos (pipeline separate from the app)

If the pipeline stays in `Stream-Dashboard---Streamlit` and the app is a different repo,
the Action must push the JSON to the app repo. Add a deploy step that either:
- checks out the app repo with a **PAT / deploy key** (stored as a secret) and commits
  `html-dashboard/data/`, **or**
- uploads the JSON as an artifact your app's own deploy picks up.

Single-repo (above) avoids this cross-repo token entirely — recommended.

---

## Live "Refresh" button (later, optional)
The button is wired to `REFRESH_ENDPOINT` (top of the `<script>` in `index.html`), null
for now. To make it do an on-demand signed pull, stand up a small serverless function
(same host/proxy) that runs the sync and returns fresh JSON, then set
`REFRESH_ENDPOINT = "/api/refresh"`. Until then, data refreshes hourly via the Action.

## Data-freshness note
The Action rebuilds the SQLite DB fresh in the runner each time (nothing sensitive is
committed except the JSON). It only commits when the JSON actually changed, so quiet
hours produce no commits.
